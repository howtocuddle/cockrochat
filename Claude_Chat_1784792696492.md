**F1 — you can drop the VDF from the beacon [de-risk].** Chaining + *fresh per-epoch entropy* alone gives forward-unpredictability. `seed_N = H(seed_{N-1} ‖ E_N)`, where `E_N` is entropy generated *during* epoch N−1. To precompute `seed_{N+5}` you'd need `E_{N+1..N+5}` — future entropy that doesn't exist yet. **Infinite compute can't predict non-existent entropy** → no tracking dictionary → your anti-precompute goal met with a hash chain, no VDF. That kills v1's worst dependency (VDF impl complexity + the hardware-gap problem where a fast adversary grinds faster than a phone).
 Residual (mild): a *present* adversary can grind `E_N` to *steer* this epoch's seed (bias, not predict). Only harm: could force two alert-glyphs to collapse into one on the wall. Cheap fix — derive the collapse map from `H(seed_N ‖ alert_content)` and require ≥k entropy contributors so one mole isn't the sole minimum. Still no VDF.



**F2 — VDF's correct home is regional-injection rate-limiting (optional).** If you keep a VDF anywhere, put its delay-cost on *originating a new Tier-2 regional alert*. It rate-limits a co-located mole seeding wide panics. Two caveats: it's parallelizable across devices → limits per-device, not aggregate, so it only makes attacker cost scale with physical footprint (which is the goal); and it does nothing to the remote van (already blocked — F3). Never on local/urgent, never on relays.



**F3 — against the remote van, PoCP already blocks injection; the hashes are secondary.** The van is outside RF range → it cannot compute *any* crowd cell → its packets fail the co-presence check regardless of time-hash. So the time-hash buys anti-precompute + anti-cross-epoch-replay, **not** anti-impersonation. Authenticity rests on the key-hash (co-presence). Don't over-trust the time-hash to authenticate anything.



**F4 — "catch the police": chaining prevents, doesn't catch. The real detector = cell-mismatch.** With chaining there's no precomputer to catch — precomputation just fails. The genuine among-us tell you're reaching for: a co-located node recomputes *its own* cell and **rejects + alarms** on any witness whose claimed cell ≠ local reality. A sniffer who captured a packet elsewhere and *replays it here* is detectable (relocation/replay detection). Formalize that as an explicit rule; it's the sniffer-catch you wanted.



**F5 — "diversity propagation" is forgeable if it trusts claimed locale-hashes in transit [important].** A message that accumulates self-claimed cell digests can be inflated: a mole writes N random 16-byte "cells" → fake diversity. And a remote aggregator *cannot* verify a remote cell — **co-presence is only verifiable by the co-present. That's a hard limit, not a bug to engineer away.** Sound version: diversity = count of distinct cells that each *locally verified* the alert, hardened by (a) fraud-proofs — occupants of a falsely-claimed cell challenge it; (b) ambient-liveness weighting — a fabricated/empty cell shows no independent traffic → discounted. Residual, and it *is* the design's point: manufacturing diversity now requires real physical presence in many populated cells = an expensive, detectable operation. You've forced the attacker into physical space. Win.



**F6 — the beacon has a liveness cliff; add local fallback + a clock floor.** Strict chaining halts if nobody publishes epoch N (sparse crowd, everyone backgrounded). Fixes: (a) **local-PoCP fallback** — chain stalls → each cell falls back to its own live ambient entropy for the anti-dictionary property (global merge degrades, doesn't die); (b) **clock floor** — accept a new seed only if ≥ ~4 min since the last, using a loose drift-tolerant local clock, to stop a fast adversary *accelerating* the chain (clock-acceleration attack). Epoch duration = max(solve/propagation, floor).



**Name the core tension:** a beacon can't max all three of forward-unpredictability, agreement (non-forking), and bias-resistance at once. For this app: unpredictability ≈ agreement > bias-resistance. Chosen point = hash-chain (agreement, cheap) + fresh per-epoch entropy (unpredictability) + accept weak, cheaply-patched bias-resistance. Reach for a VDF only if you later *prove* you need strong bias-resistance somewhere.
